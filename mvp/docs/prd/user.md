# 用户管理

## 背景
系统需要一个用户管理模块，供管理员维护后台账号。本期聚焦于账号的查询、创建与状态管控（启用/禁用），不提供账号删除能力以避免关联数据级联复杂度，亦不做批量导入。

## 用户故事
- 作为管理员，我希望能够分页查看用户列表并按状态筛选，以便快速定位目标账号。
- 作为管理员，我希望能够新建用户并确保邮箱唯一，以便避免账号重复注册。
- 作为管理员，我希望能够禁用或启用用户，以便控制账号的可用性。

## 功能点清单
- [ ] F1：分页查询用户列表（支持按状态筛选）
- [ ] F2：新建用户（邮箱唯一）
- [ ] F3：禁用用户
- [ ] F4：启用用户

## 数据实体草图
- User: { id, 姓名(name), 邮箱(email), 状态(status: 启用|禁用), 创建时间(created_at), 更新时间(updated_at) }

## 非功能需求
- 性能：分页查询在万级用户数据量下，单次响应应在合理时间内返回，避免一次性全量加载。
- 安全：仅授权管理员可访问用户管理功能；邮箱等敏感信息在展示与传输时需遵循最小暴露原则；新建与状态变更操作需留审计痕迹。
- 兼容：适配主流现代浏览器，列表分页与筛选在弱网环境下仍可正常交互。

## 验收标准（Given/When/Then）

### F1：分页查询用户列表
- Given 系统中存在 25 个用户 When 管理员请求第 2 页（每页 10 条） Then 返回第 11-20 条用户记录，且结果包含总条数 25 与总页数 3
- Given 系统中同时存在启用与禁用状态的用户 When 管理员按状态"禁用"筛选 Then 仅返回状态为"禁用"的用户，启用状态用户不出现在结果中
- Given 用户列表为空 When 管理员请求第 1 页 Then 返回空列表，总条数为 0、总页数为 0
- Given 管理员未传入状态筛选条件 When 请求用户列表 Then 返回所有状态的用户，不进行状态过滤

### F2：新建用户
- Given 邮箱在系统中未被占用 When 管理员提交合法邮箱及必填信息 Then 用户创建成功，新用户状态默认为"启用"
- Given 邮箱已被系统中其他用户占用 When 管理员提交该邮箱 Then 创建失败，明确提示"邮箱已存在"
- Given 邮箱格式非法（如缺少 @、域名不完整） When 管理员提交 Then 创建失败，明确提示"邮箱格式不正确"
- Given 必填字段缺失（如姓名为空） When 管理员提交 Then 创建失败，明确提示缺失的字段

### F3：禁用用户
- Given 目标用户当前处于"启用"状态 When 管理员对其执行禁用操作 Then 用户状态变更为"禁用"，该用户随后无法登录系统
- Given 管理员尝试禁用自身当前登录账号 When 提交禁用操作 Then 操作被拒绝，明确提示"不能禁用自身账号"
- Given 目标用户已处于"禁用"状态 When 管理员再次对其执行禁用操作 Then 操作无效，明确提示"用户已是禁用状态"

### F4：启用用户
- Given 目标用户当前处于"禁用"状态 When 管理员对其执行启用操作 Then 用户状态变更为"启用"，该用户随后可正常登录系统
- Given 目标用户已处于"启用"状态 When 管理员再次对其执行启用操作 Then 操作无效，明确提示"用户已是启用状态"
- Given 目标用户不存在（如 ID 非法） When 管理员执行启用操作 Then 操作失败，明确提示"用户不存在"

## 不确定项
- Q1：已确认——本期不提供删除用户能力，以避免关联数据级联复杂度。
- Q2：已确认——本期不做批量导入功能。
- Q3：已确认——管理员不能禁用自身当前登录账号（在 F3 中体现）。
- Q4：开放——用户列表是否需要支持按姓名或邮箱关键字搜索？当前需求仅明确"按状态筛选"，关键字搜索能力待产品负责人确认。
- Q5：开放——新建用户除邮箱外，完整的必填字段集合（如是否需要初始密码、角色分配、部门归属）尚未明确，需产品负责人补充。
- Q6：开放——禁用用户后，该用户已建立的在线会话是否需要立即失效？需产品负责人确认时效性要求。
